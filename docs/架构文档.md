# 架构文档

## 总体设计

单体架构：同一进程提供 REST API + 前端静态资源托管。

## 组件划分

### 后端（backend/src/）
- `main.rs`：服务入口，TOML 配置读取，HTTPS 启动
- `lib.rs`：路由装配，应用构建
- `auth.rs`：登录 / 登出 / 修改密码 / token 验证
- `snacks.rs`：零食 CRUD API，日期校验
- `users.rs`：用户管理，admin 权限校验
- `db.rs`：SQLite 连接池，SQL 查询
- `reminders.rs`：过期提醒计算
- `tls.rs`：HTTPS 证书加载/生成，HTTP→HTTPS 308 重定向
- `util.rs`：通用工具函数

### 前端（frontend/src/）
- `app/`：standalone components
  - `pages/login/`：登录页
  - `pages/snacks/`：库存页（增删改查、筛选、状态自动推断）
  - `pages/reminders/`：过期提醒页
  - `pages/users/`：管理员用户管理
  - `pages/change-password/`：修改密码
  - `services/`：API 通信服务

### 数据库（SQLite）
- `snacks` 表：id, name, quantity, location, purchase_date, production_date, shelf_life_days, shelf_life_unit, expiry_date, opened_at, finished_at, status, notes, created_at
- `users` 表：id, username, password_hash, is_admin, created_at
- `sessions` 表：token, user_id, expires_at

### 部署模型
- 本地运行：`./run.sh`（自签证书，HTTPS 3000）
- 容器化：Docker 镜像 + compose.yaml
- systemd 安装：/opt/snack-warehouse + snack-warehouse 用户
